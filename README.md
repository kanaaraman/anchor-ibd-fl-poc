# ANCHOR-IBD federated learning proof of concept

Three hospitals train one model together without sharing patient data and without a central party that holds the model. Each hospital runs its own NVIDIA DGX Spark and keeps its registry extract there in OMOP CDM format. The hospitals pass model weights among themselves, and a different hospital averages them each round (NVIDIA FLARE swarm learning). A coordinator only admits participants and starts jobs. A classic FedAvg mode, where the server aggregates, is included for comparison.

**[SPARKS.md](SPARKS.md)** explains how the Sparks run it, what is trained, what you need, and how to install and run it.

**[DATA.md](DATA.md)** explains the data: all patients are synthetic, how they are generated, how the generator is calibrated to published IBSEN III, SWIBREG and trial figures, and how it is validated.

The PoC follows the ANCHOR-IBD project description (Vinnova 2026-00990) and the `ibd-fl-dgx-spark` deck:

| Project description | In this PoC |
| --- | --- |
| SWIBREG and NorIBD, Sweden and Norway | Sites `rost` (Region Östergötland, SWIBREG), `oru` (Örebro University Hospital, SWIBREG), `ous` (Oslo University Hospital, NorIBD) |
| No patient data; synthetic examples only (WP2) | Synthetic cohorts with a deliberately different case mix per site, calibrated to published figures and checked by `validation/validate.py` |
| OMOP CDM, FHIR R4 data model alignment | Every site stores the standard OMOP tables; one feature extractor runs unchanged everywhere |
| Treatment response prediction for therapy selection | Clinical remission at week 52 on the index biologic (infliximab, adalimumab, vedolizumab, ustekinumab) |
| Sex-disaggregated analysis as a core requirement | Every metric is reported for women and men separately, and calibration is reported by sex |
| GDPR and EHDS; analysis without centralising data | Only weights cross the network, over mutual TLS. Optional clipping and Gaussian noise on each update |
| Deck: Sparks as independent sites, not a cluster | One NVFlare client per Spark; decentralised swarm learning with a rotating aggregator; single-Spark compose setup as step 1 |

## Data inventory

**There is no real patient data in this repository or in any result.** Every patient is synthetic, generated by code in this repository. That follows the ANCHOR-IBD project description: WP2 uses only frameworks, data model specifications and synthetic examples. [DATA.md](DATA.md) has the full write-up with every source.

### What data exists

| Dataset | Where | Size | Used for | In git? |
| --- | --- | --- | --- | --- |
| Training cohorts, one per hospital | `data/rost`, `data/oru`, `data/ous` | 600 / 450 / 350 patients | Training (80%) and validation (20%) at each site | No, regenerate with `generate_data.py` |
| Evaluation cohorts, one per hospital | `data_eval/<site>` | 3,000 patients each | Measuring every reported result; never used in training | No, regenerate |
| Calibration offsets | `ibdfl/calibration.json` | 8 numbers | Put each drug's remission rate on the published figure | Yes |
| Published targets | `validation/targets.json` | 12 figures with sources | Calibration and validation | Yes |
| Validation report | `validation/report.md` | 12 checks | Shows the data against each published figure | Yes |
| Results | `results/results.json`, `dashboard/results.js` | AUROC per site, sex, round, noise level | README numbers, dashboard, presentations | `results.js` yes, `results/` no |

Each cohort is five OMOP CDM tables (CSV):

| Table | Columns | Holds |
| --- | --- | --- |
| `person` | person_id, gender_concept_id, year_of_birth, care_site_id | Sex, age, hospital |
| `condition_occurrence` | condition_concept_id, condition_start_date, condition_source_value | Crohn's disease (ICD-10 K50) or ulcerative colitis (K51), date of diagnosis |
| `drug_exposure` | drug_concept_id, drug_exposure_start_date, drug_source_value, drug_type | Index biologic (ATC: infliximab L04AB02, adalimumab L04AB04, vedolizumab L04AG05, ustekinumab L04AC05), prior anti-TNF, azathioprine, prednisolone |
| `measurement` | measurement_concept_id, measurement_date, value_as_number | CRP, faecal calprotectin, albumin, haemoglobin (LOINC codes) |
| `observation` | observation_concept_id, value_as_number / value_as_string | Montreal location or extent, current smoking, and the outcome: clinical remission at week 52 (0/1) |

### How the data is generated

[`ibdfl/synth.py`](ibdfl/synth.py) draws each patient step by step:

1. **Hospital case mix:** diagnosis, sex, disease duration, Montreal classification, smoking, prior anti-TNF, azathioprine, prednisolone. Each hospital has its own mix. Oslo follows the IBSEN III inception cohort: 37% Crohn's, newly diagnosed, few anti-TNF-experienced patients.
2. **Lab values:** a hidden inflammation level per patient drives CRP, calprotectin, albumin and haemoglobin together.
3. **Biologic:** drawn from the hospital's drug mix. Anti-TNF-experienced patients usually switch to vedolizumab (UC) or ustekinumab (Crohn's).
4. **Outcome:** clinical remission at week 52, drawn from one formula shared by all hospitals. The formula encodes known effect directions: prior anti-TNF lowers response to another anti-TNF, vedolizumab works better in UC, women do worse on anti-TNF, and high CRP, calprotectin and smoking lower the chance of remission. A per-drug calibration offset sets the overall rate.
5. **OMOP output:** the patient is written to the five tables with real ICD-10, ATC and LOINC source codes.

The effect directions come from the IBD literature. Their sizes were chosen by the PoC team, not estimated from data.

### How the data is calibrated and validated

| Step | Command | What it does |
| --- | --- | --- |
| Calibrate | `python validation/calibrate.py` | Fits one offset per diagnosis × drug so that week-52 remission matches the published figure, and writes `ibdfl/calibration.json` |
| Generate | `python generate_data.py --out data` and `--out data_eval --eval_n 3000` | Writes the OMOP tables using the calibrated generator |
| Validate | `python validation/validate.py` | Reads the OMOP tables through the model's own feature code, compares 12 statistics with the published figures, writes `validation/report.md`, and fails if a verified figure is missed |

The published figures:

| Figure | Published | Synthetic before calibration | After | Source |
| --- | --- | --- | --- | --- |
| Oslo: share of Crohn's | 36.7% | 45.0% | 36.0% | IBSEN III, verified |
| Oslo UC: women / smokers | 45.9% / 6.2% | 49.5% / 10.3% | 46.9% / 7.1% | IBSEN III UC abstract, provisional |
| UC, vedolizumab, remission week 52 | 31.3% | 70.2% | 32.6% | VARSITY, verified |
| UC, adalimumab, remission week 52 | 22.5% | 43.4% | 23.9% | VARSITY, verified |
| UC, infliximab, remission week 54 | 34.7% | 47.2% | 34.7% | ACT 1, provisional |
| Crohn's, ustekinumab, remission week 52 | 65% | 50.9% | 66.6% | SEAVUE, verified |
| Crohn's, adalimumab, remission week 52 | 61% | 36.7% | 59.3% | SEAVUE, verified |
| UC, ustekinumab after anti-TNF | 32% | 52.6% | 31.1% | SWIBREG real-world, verified |
| Crohn's infliximab and vedolizumab; Swedish Crohn's share | 61%, 45%, 52% | | 59.4%, 43.1%, 52.4% | Assumptions, not scored |

Before calibration **0 of 9** scored checks passed; after calibration **9 of 9** pass. "Verified" means checked against the publication or its abstract. "Provisional" means seen only in a secondary source and still to verify.

**Limits.** Trial populations differ from registry patients. The checks cover averages per variable and per drug, not correlations between variables. Matching published averages does not make individual synthetic patients real, so the AUROCs show that the federated machinery works, not how well remission can really be predicted.

**Real data later:** SWIBREG and NorIBD under ANCHOR-IBD governance, or trial data by application (YODA Project, Vivli, AbbVie). See [DATA.md](DATA.md).

## Results

Synthetic data calibrated to published figures (all 9 scored checks pass, see [DATA.md](DATA.md)), 30 rounds of 3 local epochs, mean of 5 training seeds. Every strategy picks its stopping point on a validation split. Scores are measured on 3,000 new synthetic patients per site who took no part in training.

| AUROC | Östergötland | Örebro | Oslo | All sites |
| --- | --- | --- | --- | --- |
| Local only (each site alone) | 0.762 | 0.741 | 0.736 | 0.743 |
| **Federated (swarm / FedAvg)** | **0.768** | **0.757** | **0.742** | **0.758** |
| All records copied to one place (ceiling, not allowed in reality) | 0.770 | 0.758 | 0.744 | 0.760 |

- Federated learning beats local-only training at every site and recovers about 88% of the gain you would get by copying all records to one place. No patient record leaves a site. The improvement is modest because the cohorts are small and the model is simple.
- By sex (all sites): the federated model scores 0.756 for women and 0.756 for men. Predicted remission rates match observed rates: women 38.8% vs 39.8%, men 45.4% vs 46.2%.
- Privacy versus accuracy, measured as federated AUROC: 0.758 without noise; 0.755, 0.750 and 0.695 at noise multipliers 0.05, 0.1 and 0.2. Up to 0.1, training together with noise still beats training alone (0.743); at 0.2 it does not. No formal ε is computed; a privacy accountant belongs in the follow-on project.
- These AUROCs measure how well the model recovers the synthetic ground truth. They say nothing about real-world predictive performance.
- Each update is 4.6 KB per site per round (1,185 weights).

Open `dashboard/index.html` for the interactive version, which includes a training replay, a cross-site matrix, calibration by sex and the privacy trade-off.

## Run it

Use Python 3.10+ on Linux or WSL (NVFlare does not run natively on Windows).

```bash
pip install -r requirements.txt
python generate_data.py --out data                       # 3 sites, OMOP CSVs
python generate_data.py --out data_eval --eval_n 3000    # held-out evaluation cohorts (simulation only)
python validation/validate.py                            # check the data against published figures
python simulate.py                                       # all strategies, ~2 min on CPU; writes dashboard/results.js
python -m http.server 8000 --directory dashboard         # open http://localhost:8000
```

The same training code under NVFlare, three simulated hospitals in one process:

```bash
python nvflare_job/job.py --workflow swarm --env sim --data_root $PWD/data --rounds 30
```

`simulate.py` reports FedAvg numbers. Swarm computes the same weighted average; it only moves the averaging step from the server to a rotating hospital.

### On DGX Sparks

**Step 1: one Spark, four containers.** This step follows the deck's "simulate 3 hospital sites on a single Spark first". It uses the same certificates and job as step 2.

```bash
nvflare provision -p deploy/project.yml -w deploy/workspace
python generate_data.py --out data
KIT=deploy/workspace/anchor_ibd/prod_00 docker compose -f deploy/docker-compose.yml up -d --build
```

**Step 2: one Spark per hospital.** Copy each hospital only its own startup kit from `deploy/workspace/anchor_ibd/prod_00/<site>`; the kit contains that site's private key. Make `anchor-fl-server` resolve to the server host. The hospital needs only outbound TCP 8002 to the server.

```bash
docker build -f deploy/Dockerfile -t anchor-ibd-fl .                     # on every host
deploy/run_site.sh server deploy/workspace/anchor_ibd/prod_00/anchor-fl-server  # server host
deploy/run_site.sh client <kit dir for this site> /data/omop <server ip>        # each hospital Spark
```

**Submit the job** from the admin's machine:

```bash
python nvflare_job/job.py --workflow swarm --env prod --startup_kit deploy/workspace/anchor_ibd/prod_00/admin@rise.se --data_root /data
```

The full step-by-step guide is in [SPARKS.md](SPARKS.md).

Add `--dp_noise 0.05` to clip each update and add Gaussian noise before it leaves the hospital.

## Layout

| Path | What it is |
| --- | --- |
| `ibdfl/synth.py` | Synthetic cohort generator and ground-truth response model (drug × phenotype and drug × sex effects) |
| `ibdfl/calibration.json` | Fitted offsets that put each drug's remission rate on the published figure |
| `validation/` | `targets.json` (published figures with sources), `calibrate.py`, `validate.py`, `report.md` |
| `ibdfl/vocab.py` | OMOP concepts and source codes |
| `ibdfl/features.py` | OMOP tables → 19 features; the same code at every site |
| `ibdfl/model.py`, `ibdfl/train.py` | MLP, local training, metrics (AUROC, Brier, by sex), update clipping and noise |
| `simulate.py` | Local vs FedAvg vs FedAvg+DP vs pooled, in one process |
| `nvflare_job/client.py`, `nvflare_job/job.py` | NVFlare 2.9 client script; swarm (default) and FedAvg recipes, sim or prod |
| `deploy/` | `project.yml` for provisioning, Dockerfile, single-Spark compose, per-site launcher |
| `dashboard/` | Static demo page; `results.js` is written by `simulate.py` |
| `demo/run_demo.sh` | One-command live demo: certificates, coordinator and 3 hospital clients as separate processes, swarm job, narrated output (Linux or WSL) |
| `demo/presentation.html` | 18-slide animated presentation; open in a browser, arrow keys to move, N for speaker notes, F for full screen |

`data/`, `data_eval/`, `results/` and `deploy/workspace/` (which holds private keys) are git-ignored.
