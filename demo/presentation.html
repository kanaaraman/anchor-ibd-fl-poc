The problem

One registry alone is too small

Treatment-response and subgroup studies are underpowered in each country, and patient data cannot simply be copied across the border under GDPR, national law and EHDS.

Source: ANCHOR-IBD project description (Vinnova 2026-00990), approximate figures

The idea

Train together, keep data home

No patient record moves

Each hospital trains on its own OMOP extract. Only model weights travel: 4.6 KB per hospital per round.

No central model holder

Hospitals take turns averaging the model. The coordinator only starts the job and never sees the weights.

One data model, one code

Every site stores OMOP CDM tables, so the same feature code runs unchanged in Sweden and Norway.

How it works

Swarm learning, round by round

Every hospital trains on its own patients. One hospital collects the updates, averages them and sends the new shared model back. Next round, another hospital averages.

Scores: each hospital’s AUROC for the shared model.

Synthetic data. NVFlare picks the averaging hospital at random; the order shown is illustrative.

How it works

One round in four steps

1

Train locally

Each hospital trains the shared model for 3 epochs on its own patients, on its own Spark’s GPU.

2

Send to this round’s averager

One hospital is picked at random. The others send it their weights, encrypted for that hospital only.

3

Average

The averaging hospital weights each update by its number of training steps and combines them.

4

Share and repeat

The new shared model goes back to every hospital. The best one, by validation loss, is kept.

How it works

Swarm removes the central model holder

Server-based FedAvg

One server receives every update and holds the model. A single point of trust.

Honest about compute

This model trains in seconds even on a CPU. The Spark is the hospital’s own GPU node for the next models: endoscopy images and clinical text.

What we train

Will this patient respond to this biologic?

Outcome

Clinical remission 52 weeks after starting the biologic

Biologics compared

Infliximab · adalimumab · vedolizumab · ustekinumab

Model

Small neural network, 19 → 32 → 16 → 1, output = probability of response

19 inputs, read from OMOP CDM tables

Age · sex · Crohn’s disease or ulcerative colitis · disease duration · Montreal location and extent · smoking · prior anti-TNF · azathioprine · prednisolone · CRP · faecal calprotectin · albumin · haemoglobin · biologic started

Research model on synthetic data. Not for clinical decisions.

What you need

  
Hardware, network, software, data, people

  

    
HardwareOne DGX Spark per hospital; one small Linux host as coordinator (no GPU)

    
NetworkDNS name for the coordinator; ports 8002 and 8003 open there only; hospitals outbound only

    
SoftwareDGX OS with Docker, NVIDIA PyTorch container from NGC, NVFlare 2.9.0

    
DataAn OMOP CDM extract per hospital; real data needs ethics approval, a DPIA and data agreements

    
PeopleAn IT contact at each hospital; one admin at RISE who distributes the kits
